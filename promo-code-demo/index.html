Afterpay shoppers used to leave checkout to redeem an offer. With no engineering capacity allocated, I planned and built redemption directly into the payment flow.

The product

The feature, in 20 seconds.

A real sandbox checkout, beginning at the order summary so the recording stays focused on the promo interaction.

  1. 01The customer enters a promo code without leaving checkout.
  2. 02The offer is validated against the campaign and customer.
  3. 03The discount appears immediately in the order summary.

The problem

Remove the detour.

A useful offer had a poor journey. Redemption required customers to leave checkout, switch to the Afterpay app, then return to the merchant.

Before

The app detour

  1. Start checkout
  2. Leave for the Afterpay app
  3. Redeem the offer
  4. Return and finish
Now

One continuous flow

  1. Start checkout
  2. Enter the promo code
  3. See the discount
  4. Complete payment

How I built it

No engineering team. So I became the builder.

I remained accountable for the product problem and used AI agents as planning and coding collaborators. Experienced checkout engineers reviewed the direction and each increment before release.

01 · Plan

Create the implementation path

Agent 1 translated the idea into surfaces, dependencies, risks, tests and a delivery sequence.

02 · Challenge

Review with fresh context

Agent 2 looked for missing cases, unsafe assumptions and opportunities to simplify.

03 · Align

Bring in engineering judgement

Checkout engineers reviewed the plan so it matched the system and its operating standards.

04 · Sequence

Make every change reviewable

The foundation, interface, integration, analytics and hardening were split into clear increments.

05 · Build

Implement one increment at a time

I tested each piece, incorporated feedback and only then moved to the next increment.

06 · Refine

Observe and iterate

Edge cases, targeting and visual fidelity improved through repeated comparison—not one generated answer.

Three lessons.

Learning curve

Local testing

I learned the checkout test harness and built the right scenarios for visibility, success and failure.

Planning miss

Review time

Writing changes was only part of delivery; owning-team availability was a real dependency.

Agent misconception

Visual fidelity

Quality still required careful comparison, precise feedback and many small iterations.
