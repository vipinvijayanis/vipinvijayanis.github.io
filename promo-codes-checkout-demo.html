01 · The problem

A good offer had a bad journey.

Shoppers had to leave checkout, redeem in the Afterpay app, then return. At the same time, broad discounts spent incentive on people who may have purchased anyway.

Before

The app detour

Two surfaces and multiple places to abandon.

  1. See promo code on merchant sites
  2. Leave checkout and open the Afterpay app High friction
  3. Find and redeem the promo
  4. Return to the merchant and finish Context switch
Now

Redemption in checkout

One surface from code to purchase.

  1. See promo code on merchant sites
  2. Select Afterpay at the merchant
  3. Enter the code in checkout
  4. See the total and payments update
  5. Confirm the purchase

03 · How I built it

There was no engineering team available—so I became the builder.

I was the product manager for the problem, but there was no allocated engineering capacity to implement the solution. Rather than leave the idea on a roadmap, I used AI agents as planning and coding collaborators, with experienced engineers reviewing the approach and the changes.

The decision

Turn a resourcing constraint into a hands-on product build.

The goal was not to work around engineering standards. It was to create a reviewable plan, get the right technical confidence, then deliver the feature in small increments that the owning teams could safely assess.

0 dedicated engineers allocated to build the feature
The agent-assisted delivery process
STEP 01 · AGENT 1

Create the implementation plan

I used the first agent to translate the product idea into an end-to-end technical plan: surfaces, dependencies, risks, testing, and delivery sequence.

STEP 02 · AGENT 2

Independently challenge it

A second agent reviewed the plan with fresh context, looking for missing cases, unsafe assumptions, and places where the design could be simpler.

STEP 03 · HUMAN REVIEW

Get engineers comfortable

I asked engineers familiar with checkout to review the direction before implementation, so the approach matched the system and its operating standards.

STEP 04 · DELIVERY DESIGN

Split the work into small increments

We agreed how to separate the foundation, interface, integration, analytics, and hardening so each change stayed understandable and reviewable.

STEP 05 · BUILD

Implement one increment at a time

I worked through the sequence with the agents, tested each piece, incorporated review feedback, and only then moved to the next increment.

STEP 06 · REFINE

Test, observe, and iterate

The final experience came from repeated cycles across behavior, edge cases, visual fidelity, and campaign targeting—not from a single generated solution.

The three hardest parts
Biggest learning curve

Local testing

Testing checkout locally was new to me. I had to learn the existing test harness—and where needed shape the right mocks—to reproduce the combinations where the promo field should appear, stay hidden, succeed, or fail.

Biggest planning miss

Review time

I underestimated the calendar time required for the owning teams to review each change and merge it safely. Writing the change was only part of the delivery timeline; review availability was a real dependency.

Biggest agent misconception

Pixel-perfect design

Giving an agent the design did not produce a faithful interface automatically. Reaching the intended quality took countless visual comparisons, precise feedback, and small iterations across spacing, type, states, and motion.

The lesson: agents accelerated planning and implementation, but they did not replace product judgement, technical review, testing discipline, or the patience required for craft.
